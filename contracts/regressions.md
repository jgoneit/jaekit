# Common regression connections

[regressions.json](regressions.json) is the finite registry for five current Jaekit invariants. Each route names its product consumers, public contract, general property, original example, related input families, supported boundary, selected regression, and public follow-up when unresolved. It is reviewed source, not an inference from private goal records. Changes that introduce another consumer of I1–I5 must add that route and its protection or explicit gap.

| ID | Property | Consumers |
| --- | --- | --- |
| I1 | Current-file checks are independent of private material and unnecessary history | repository producers, public preservation checks, stored proof consumers |
| I2 | Actual result meaning survives producer, current/baseline judgment and saved evidence | reference and repository producers, evidence validation, CLI and status |
| I3 | Request binding and uncertainty survive observation consumers | native trace decoding, shell reading, collected execution and release observation |
| I4 | Required tools and selected failures remain visible | shared local/CI entrypoint, shell launchers and both CI groups |
| I5 | Public scanners distinguish rules and normal fixtures without broad evasion | tracked public path and content scanning |

`protected` means that the named property has the listed regression connected to the common verification group. It does not claim that every possible input or every property of that source file is covered. `gap` is an unresolved property and is never counted as protection. Existing protection must not be demoted merely to avoid a failing regression. The integrated registry connects the producer, observation and scanner fixes to their actual regression selectors. Stable route IDs retain their original names (including a historical `-gap` suffix); the `status` field is authoritative. Issue links preserve the source of each correction and do not by themselves establish protection. `protected` still describes the listed property and selection, not a recorded pass of the combined tree.

Run `python3 tools/regression_map.py --format json` to validate the registry. The result says `assurance: selection-only`. It checks public source paths, explicit test definitions and the supported unconditional discovery statements in `tools/verify.py`. A commented name, absent test, unselected file, or unsupported selection control flow does not establish selection. Python class/method inspection establishes definition presence only; `unittest` execution is checked separately. Group-body parsing does not prove the main dispatcher or CI wiring: the existing `tools/workflow-checks/test_verify.py` and `test_repository.py` cover those connections. The parser is intentionally narrow: when the verification implementation changes beyond its supported statements, update and verify the selector parser or report that it cannot establish the connection.

This command does **not** execute a test or attest remote CI. The shared documentation group loads the registry regression through `tools/workflow-checks/test_regressions.py`; the existing Go group executes the protected Go and shell suites. Run `python3 tools/verify.py` on the actual integrated tree to execute both groups, including the real product regressions. A synthetic invocation fixture proves selection and failure forwarding only. A test file's existence, a selection-only report, a product test result, and a remote CI result are distinct evidence.

For an explicit prior **public registry snapshot**, `python3 tools/regression_map.py --previous <public-snapshot.json> --format json` reports removed or demoted protection, scope edits, and narrower or replaced check sets. It does not fetch Git history or infer a prior private goal. Record why a replacement preserves the property and link the replacement regression in the source change. The comparison marks changes for review; it does not judge semantic equivalence automatically. Changing a goal or branch name is not a reason to remove a route.

When integrating a fix, preserve the stable route ID, update its sources and selectors, and distinguish the original case from its generalized input family. For every protected route, execute its normal and relevant violation/error/unsupported fixtures. I2 needs the producer-to-Core current and baseline boundary; I3 needs uncertainty and identity at the final consumer; I4 needs actual selected launch paths; I5 needs both normal scanner sources and forbidden inputs. Capture the tested commit/tree and result in the change's verification record. Results from individual branches do not describe a combined tree until that tree has been tested.

The registry adds no installed tool, network, model, history download, or private-record requirement. Documentation-only verification retains its existing dependencies. Public synthetic fixture treatment is local to the relevant scanner; it is not a repository-wide instruction to split strings or exempt filenames. Longer-term defect recurrence and execution cost remain follow-up observations, not claims made by this registry.

The integrated additions remain within I1–I5: explicit retention inputs protect I1; result adapters, saved findings and evidence-reporting contracts protect I2; bounded archive inputs and explicit Spec observation boundaries protect I3. Their rows state which checks use actual local processes and which validate synthetic document/protocol fixtures. These additions do not broaden the registry into every behavior of those features. Existing protected route IDs, scopes and regression selectors are retained. Run the combined tree through the shared entrypoint before describing the integration as verified.
