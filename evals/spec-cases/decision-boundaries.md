# 판정 경계와 예시 범위

Status: 초안

가상 시나리오이며 실제 사용자 대화나 실행 기록이 아닙니다. 아래 목표 예시는 평가에서 기대하는 문서 결과입니다. 정적 검사와 변형 비교는 문서 연결만 확인하며 새 모델의 실제 행동을 관측하지 않습니다.

## 요청

A. 실행 관찰 판독기의 출력 문자열을 실행으로 인정하지 않도록 목표를 작성해 주세요. 큰따옴표 문자열은 표본입니다. Bash만 지원하며, 요청과 세션 중 어떤 단위인지와 판독 불가의 결과는 아직 정하지 않았습니다.

B. 공개 계약대로 Bash·Zsh와 shallow clone 환경에서 선택한 구버전 설치 자료만 정리하는 목표를 작성해 주세요. 계약은 공백·줄바꿈 이름과 symlink·다른 위치의 같은 이름을 포함하여 관계없는 모든 파일을 보존한다고 정합니다. 동시 호출에도 선택 범위 밖 추가·삭제·변경이 없어야 합니다. 사례는 표본이고 fixture·스냅샷 방법은 맡깁니다.

C. 입력은 `a`와 `b` 두 값만 허용하고 그 밖은 거부하는 목표를 작성해 주세요. 이 둘은 전체 목록입니다.

## 사용자 답

A의 미결정 질문에 대한 합성 답: “요청 단위로 판단하고 다른 요청의 근거를 쓰지 않는다. 알 수 없는 입력은 근거 불충분으로 보여 준다.”

B의 공개 계약과 C의 전체 목록·거부 정책은 이미 결정되어 있으므로 다시 묻지 않습니다. 프레임워크·fixture·모델·파일 배치는 묻지 않아야 할 것입니다. 작은 오탈자 수정은 기존 [readme-typo](readme-typo.md)의 질문 상한 0을 유지하며 관련 없는 환경표를 더하지 않습니다.

## 목표 예시: observation-draft

```markdown
# 실행 관찰의 판정 경계
Status: Draft
Criteria-Format: nested/1
## 목표·범위
Bash 실행 관찰에서 실행되지 않은 텍스트를 근거로 쓰지 않는다. 다른 셸 지원은 범위 밖이다.
## 결정과 근거
큰따옴표 문자열은 표본이고 Bash만 지원한다. 출처: 요청 A.
## 사용 시나리오
| 종류 | 시나리오 | 조건 |
| --- | --- | --- |
| 경계 | 출력·주석과 실행되지 않은 분기는 실행 근거가 아니다 | AC-1 |
| 유지 | 실제 실행한 지원 입력의 근거는 보존된다 | AC-2 |
## Acceptance Criteria
- **AC-1** 실행하지 않은 텍스트를 실행 근거로 인정하지 않는다. 큰따옴표 출력은 대표 사례이며 예시 밖의 비실행 텍스트에도 같은 성질이 적용된다.
- **AC-2** 실제 실행한 지원 입력의 근거는 계속 인식된다.
## Open Decisions
관측 단위는 요청인가 세션인가? 판독할 수 없는 입력은 어떤 결과인가?
```

## 목표 예시: observation-ready

```markdown
# 실행 관찰의 판정 경계
Status: Ready
Criteria-Format: nested/1
## 목표·범위
Bash 실행 관찰을 요청 단위로 판단한다. 지원하지 않는 입력은 실행 근거로 쓰지 않는다.
## 결정과 근거
관측 단위는 요청이며 판독 불가는 근거 불충분이다. 출처: 사용자 답 A. Bash 지원과 표본 범위의 출처는 요청 A다.
## 사용 시나리오
| 종류 | 시나리오 | 조건 |
| --- | --- | --- |
| 경계 | 같은 세션의 다른 요청이나 출력·주석을 실행 근거로 쓰지 않는다 | AC-1 |
| 유지 | 해당 요청에서 실제 실행한 지원 입력의 근거는 보존된다 | AC-2 |
## Acceptance Criteria
- **AC-1** 해당 요청에서 실제로 실행하지 않은 텍스트는 실행 근거가 아니다. 출력·주석은 표본이며 예시 밖의 비실행 텍스트에도 적용된다. 판독 불가는 근거 불충분이고 다른 요청의 근거는 섞이지 않는다.
- **AC-2** 해당 요청에서 실제 실행한 지원 Bash 입력의 근거는 계속 인식된다.
## Open Decisions
없음.
```

## 목표 예시: cleanup-ready

```markdown
# 선택한 구버전 설치 자료 정리
Status: Ready
Criteria-Format: nested/1
## 목표·범위
Bash·Zsh와 shallow clone에서 선택한 구버전 설치 자료만 정리한다. 다른 플랫폼 지원 추가는 범위 밖이다.
## 결정과 근거
출처: 공개 계약 B. 전후 집합에서 선택한 구버전 자료만 제거될 수 있고 관계없는 파일은 보존된다. 시험 fixture와 스냅샷 방식은 구현자가 선택한다.
## 사용 시나리오
| 종류 | 시나리오 | 조건 |
| --- | --- | --- |
| 흐름 | 선택한 구버전 설치 자료가 정리된다 | AC-1 |
| 유지 | 줄바꿈 이름·symlink·다른 위치의 같은 이름과 동시 호출에서도 관계없는 파일이 보존된다 | AC-2 |
## Acceptance Criteria
- **AC-1** 선택한 구버전 설치 자료는 지원 환경에서 제거된다.
- **AC-2** 호출 전후 선택 범위 밖의 모든 파일은 추가·삭제·변경되지 않는다. 공백·줄바꿈 이름, symlink, 같은 이름과 동시 실행 순서는 표본이며 목록 밖의 관계없는 파일도 보존된다. 대상인지 판단할 수 없으면 해당 파일을 보존한다.
## Open Decisions
없음.
```

## 기대 결과와 평가 경계

A는 미결정을 구현자 선택으로 숨기거나 Ready로 만들지 않습니다. 사용자 답 뒤 같은 AC-1·AC-2와 문서 형식을 보존합니다. B·C는 이미 정한 결과를 다시 묻지 않고 출처를 연결합니다. 모든 예시는 방법이나 실행 명령이 아닌 결과로 조건을 쓰며 문서 작성 뒤 구현을 시작하지 않습니다. 실제 모델의 질문·문서 생성 결과는 별도 평가 기록에서 확인합니다.
