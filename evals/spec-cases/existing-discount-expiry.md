# 기존 기능 수정: 할인 코드 만료일

평가용 가상 시나리오입니다. 실제 사용자 대화나 실행 기록이 아닙니다([설명](README.md)).

Status: 초안(사람 확인 전)

## 요청

"할인 코드에 만료일을 둘 수 있게 해줘"

## 저장소 맥락

- 결제 단계에서 할인 코드를 입력하면 정해진 비율만큼 깎인다(`src/checkout/discount.ts`).
- 지금 할인 코드에는 만료일이 없고, 운영 중인 코드가 수십 개 있다(`discount_codes` 테이블).
- 주문을 취소하면 환불 금액을 계산할 때 할인 코드를 다시 읽는다(`src/orders/refund.ts`).

## 사용자 답

- 기존 코드: 만료일 없이 지금처럼 계속 쓸 수 있어야 한다
- 만료 기준 시각: 서비스 기준 시간대의 그날 끝
- 그 밖의 질문: 알아서 정해 줘

## 기대 결과

- 물어야 할 것
  - 만료일이 없는 기존 코드를 어떻게 다룰지
  - 만료 기준 시각(시간대, 그날의 시작인지 끝인지)
- 들어가야 할 조건(필수)
  - 만료일이 지난 코드는 결제에서 거절되고 이유가 표시된다
  - 만료일 전에는 지금과 같은 금액이 깎인다
  - **유지**: 만료일이 없는 기존 코드는 지금과 같이 적용된다
  - **유지**: 할인 코드를 쓰지 않은 결제 금액은 바뀌지 않는다
  - **유지**: 만료일이 지난 뒤 취소된 주문도 결제 때 깎인 금액을 기준으로 환불된다
- 들어가면 안 되는 것
  - 사용 횟수 제한, 코드 일괄 생성, 만료 알림
- 끝난 모습
  - 지금 동작(만료일 없음, 결제 때 할인 적용)이 근거 파일 경로와 함께 사실로 적혀 있다
  - 환불 계산처럼 바뀌는 동작이 닿는 곳이 유지 조건에 있거나, 해당 없음으로 본 이유가 대화로 보고된다
- 질문 상한: 3
