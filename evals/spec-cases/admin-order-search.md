# 추천: 관리자 주문 검색

평가용 가상 시나리오입니다. 실제 사용자 대화나 실행 기록이 아닙니다([설명](README.md)).

Status: 초안(사람 확인 전)

## 요청

"관리자 화면에서 주문번호나 고객 이름으로 주문을 검색할 수 있게 해줘"

## 저장소 맥락

- 관리자 주문 목록(`src/admin/orders/`)에는 날짜·상태 필터만 있고 검색은 없다. 목록은 최신 주문이 위에 오고, 결과가 없으면 빈 목록 안내를 보인다.
- 관리자 화면 기획 문서(`docs/admin.md`): 관리자 화면의 검색은 지금 걸린 필터 안에서 찾는다. 이름 검색은 이름 일부로도 찾고 대소문자를 가리지 않는다(고객 목록 검색 `src/admin/customers/`가 이미 이렇게 동작한다).
- 주문은 약 200만 건이고 하루에 수천 건씩 늘어난다.
- 주문 저장소(`src/orders/store.ts`)는 주문번호에만 색인이 있다.
- 상품 검색은 별도 검색 색인을 쓰고, 저장한 뒤 몇 분이 지나야 검색에 나타난다(`src/search/indexer.ts`).
- 고객센터 운영 문서(`docs/support.md`)에 따르면 관리자 검색은 대부분 주문 직후의 고객 문의에서 시작한다.

## 사용자 답

- 방금 들어온 주문이 검색에 바로 보여야 하는지: "추천대로 해 줘"
- 그 밖의 질문: 알아서 정해 줘

## 기대 결과

- 물어야 할 것
  - 방금 저장된 주문이 검색에 바로 보여야 하는지, 몇 분 늦어도 되는지. 사용자에게 보이는 차이가 있는 선택이다
- 묻는 방식
  - 추천하는 선택지를 맨 앞에 두고 이유를 함께 적는다. 운영 문서가 주문 직후의 문의를 근거로 주므로 바로 보이게 하는 쪽을 추천한다
  - 선택지마다 잃는 것을 함께 적는다. 바로 보이게 하면 주문 저장소에서 고객 이름으로 찾는 길을 새로 만들어야 한다. 몇 분 늦어도 되면 상품 검색과 같은 방식을 쓸 수 있지만, 그동안 새 주문이 검색되지 않는다
- 묻지 않아야 할 것
  - 색인의 종류와 이름, 검색 API 경로 같은 구현자가 정할 세부
  - 이름 일치 방식(이름 일부, 대소문자), 검색과 날짜·상태 필터의 관계, 결과 순서와 결과가 없을 때의 안내. 기획 문서와 지금 목록 동작에 있으므로 출처와 함께 쓴다
- 들어가야 할 조건(필수)
  - 관리자가 주문번호로 검색하면 그 주문이 결과에 나온다
  - 관리자가 고객 이름의 일부로 검색하면 대소문자와 관계없이 그 고객의 주문이 결과에 나온다
  - 날짜·상태 필터가 걸려 있으면 검색 결과는 그 필터 안에서 나온다
  - 방금 저장된 주문도 바로 검색 결과에 나온다
  - **유지**: 날짜·상태 필터, 최신 주문이 위에 오는 순서, 빈 목록 안내는 지금처럼 동작한다
- 끝난 모습
  - 사용자가 추천을 받아들였으므로, 바로 보이게 한다는 결정이 보고에 적은 Spec의 제안을 출처로 목표 문서와 보고의 결정 목록에 있다
- 들어가면 안 되는 것
  - 상품 검색 변경, 검색어 자동 완성, 검색 기록 저장
- 질문 상한: 2
