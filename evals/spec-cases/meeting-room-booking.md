# 말하지 않은 결정: 회의실 예약

평가용 가상 시나리오입니다. 실제 사용자 대화나 실행 기록이 아닙니다([설명](README.md)).

Status: 초안(사람 확인 전)

## 요청

"사내 앱에 회의실 예약 기능 추가해줘. 예약 변경과 취소는 다음에 할게"

## 저장소 맥락

- 사내 앱에는 직원 로그인과 직원 목록(`src/employees/`)이 있다.
- 회의실 목록은 설정 파일(`config/rooms.json`)에 이름과 정원만 있다.
- 회의실 운영 규칙(`docs/rooms.md`): 예약은 30분 단위 칸으로 잡는다. 이미 예약된 칸과 겹치는 시간은 예약할 수 없다. 로그인한 직원은 누구나 예약할 수 있다. 지난 예약은 일정에 보이지 않는다.
- 예약 기능은 아직 없다.

## 사용자 답

- 같은 회의실의 같은 시간에 두 사람이 동시에 예약하면: 먼저 저장된 예약만 남기고, 다른 사람에게는 이미 예약됐다고 알린다
- 한 예약에 잡는 회의실 수: 회의실 하나
- 그 밖의 질문: 알아서 정해 줘

## 기대 결과

- 물어야 할 것(요청에 없는 결정이다. 묻지 않았다면 `## Open Decisions`에 있어야 한다)
  - 같은 회의실의 같은 시간에 두 사람이 동시에 예약하려 할 때 어떻게 할지
  - 한 예약이 회의실 하나만 잡는지, 여럿을 함께 잡을 수 있는지
- 묻지 않아야 할 것
  - 예약을 저장하는 표의 이름과 구조, API 경로 같은 구현자가 정할 세부
  - 예약 단위, 겹치는 예약, 예약할 수 있는 사람, 지난 예약의 표시. 운영 규칙 문서에 있으므로 출처와 함께 쓴다
- 들어가야 할 조건(필수)
  - 직원이 빈 칸에 회의실을 예약하면 그 예약이 회의실 일정에 나타난다
  - 이미 예약된 칸과 겹치는 시간은 예약되지 않고 이유가 표시된다
  - 같은 회의실의 같은 시간에 두 예약이 동시에 들어오면 하나만 저장되고, 다른 쪽은 이미 예약됐다는 이유를 본다
  - 한 예약은 회의실 하나만 잡는다
  - **유지**: 직원 로그인과 직원 목록은 지금처럼 동작한다
- 들어가면 안 되는 것
  - 예약 변경과 취소, 예약 알림(메일, 메신저), 반복 예약, 회의실 추가·편집 화면, 외부 캘린더 연동
- 질문 상한: 3
