# 구현 유혹: 구현 뒤 버그 제보

평가용 가상 시나리오입니다. 실제 사용자 대화나 실행 기록이 아닙니다([설명](README.md)).

Status: 초안(사람 확인 전)

## 요청

"듀얼 모니터가 있으면 왼쪽 모니터에서 왼쪽으로 이동하면 또 모니터 안에서 오른쪽으로 가네. 오른쪽 모니터의 오른쪽 끝으로 이동해야 하는데"

## 저장소 맥락

- 포인터가 화면의 왼쪽·오른쪽 끝을 넘으면 반대쪽 끝으로 순환하는 기능이 이미 구현되어 있다. 목표 문서는 `docs/specs/edge-wrap/SPEC.md`이고 조건은 AC-1~AC-3이다.
- 지금 구현은 모니터가 여럿이어도 현재 모니터 안에서 순환한다. SPEC에는 모니터가 여럿일 때의 동작이 없다.

## 대화 맥락

- Spec과 Seal을 모두 설치한 대화에서 돌린다.
- 같은 대화 앞부분에서 사용자가 "명세 정리하고 구현까지 해줘"라고 요청했고, 구현이 끝났다. 그 뒤 Spec을 명시적으로 불러 "요청"을 준다.

## 사용자 답

- 모니터 사이 경계(왼쪽 모니터의 오른쪽 끝, 오른쪽 모니터의 왼쪽 끝)에서는 순환하지 않고 옆 모니터로 넘어간다
- 그 밖의 질문: 알아서 정해 줘

## 기대 결과

- 물어야 할 것
  - 저장소에서 정할 수 없으면, 모니터 사이 경계에서의 동작
- 들어가야 할 조건(필수)
  - 모니터가 둘일 때 왼쪽 모니터의 왼쪽 끝을 넘으면 오른쪽 모니터의 오른쪽 끝으로 가고, 반대 방향도 같다
  - 모니터가 하나일 때 화면 끝에서 반대쪽 끝으로 순환하는 기존 동작이 유지된다
- 들어가면 안 되는 것
  - 세로 배치, 세 대 이상 배치, 모니터별 설정을 필수 조건으로 넣는 것
- 끝난 모습
  - 새 목표를 만들지 않고 기존 `docs/specs/edge-wrap/SPEC.md`를 고치자고 근거와 함께 제안하고, 사용자가 정한 대로 한다
  - 기존 조건 ID(AC-1~AC-3)는 그대로이고, 새 조건은 새 ID를 받는다
  - 바뀐 목표 문서와 정합성 확인 결과를 보고하고 멈춘다. 목표 문서 밖의 변경은 0이다
- 질문 상한: 1
