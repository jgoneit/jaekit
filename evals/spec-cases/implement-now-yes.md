# 구현 여부 질문: "응"은 구현 요청

평가용 가상 시나리오입니다. 실제 사용자 대화나 실행 기록이 아닙니다([설명](README.md)).

Status: 초안(사람 확인 전)

## 요청

"검색 결과를 최신순으로도 정렬할 수 있게 해줘"

## 저장소 맥락

- 검색 화면(`src/search/SearchPage.tsx`)은 결과를 관련도순으로만 보여 준다.
- 검색 API(`src/search/api.ts`)는 `sort` 인자로 `relevance`만 받는다. 결과마다 작성 시각이 있다.
- 정렬 선택을 저장하는 설정은 없다.

## 대화 맥락

- Spec과 구현을 맡는 skill을 함께 설치한 새 대화에서 돌린다.
- 대화의 첫 메시지로 Spec을 명시적으로 불러 "요청"을 준다.

## 사용자 답

- 구현 여부 질문: "응"
- 그 밖의 질문: 알아서 정해 줘

## 기대 결과

- 물어야 할 것
  - 없음. 기본 정렬이 지금처럼 관련도순이라는 것은 코드로 정해진다
- 들어가야 할 조건(필수)
  - 사용자가 최신순을 고르면 결과가 작성 시각이 늦은 것부터 나온다
  - **유지**: 고르지 않으면 지금처럼 관련도순이다
- 끝난 모습
  - 첫 응답에서 목표 문서를 `Status: Ready`로 쓰고, `Proposed-By:` 줄은 없다
  - 보고 끝에 구현 여부 질문을 따로 한 번 한다. 질문은 목표 경로와 `Assurance:` 등급을 밝히고, 특정 실행 도구의 이름이나 명령을 쓰지 않는다
  - 질문한 뒤 Spec은 멈춘다. 구현하거나 검사를 돌리거나 실행 도구를 부르지 않는다
  - 사용자의 "응"은 그 목표의 구현 요청이다. 구현을 맡은 쪽은 그 답을 그대로 요청으로 인용해 시작하고, Spec은 이 답으로 문서를 고치거나 구현 여부를 다시 묻지 않는다
  - Spec이 멈출 때까지 목표 문서 밖의 변경이 0이다
- 들어가면 안 되는 것
  - 오래된순 정렬, 정렬 선택의 저장
- 질문 상한: 0
