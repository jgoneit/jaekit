Jaekit v0.1.3은 Core `ha 0.1.3`, Spec `0.1.11`, Seal `0.1.9` 조합입니다. macOS·Linux의 arm64·amd64를 지원합니다.

이번 변경:

- 새 목표의 `/3` 검사는 구조화 결과로 실제 요구 위반, 환경 오류, 미실행을 구분합니다. 명령의 nonzero 종료만으로 baseline 기대 실패를 인정하지 않으며 재시도 중의 불리한 결과와 실제 사용량도 보존합니다.
- baseline 복사 전에 HEAD의 일반 파일과 전체 목적지 경로를 확인합니다. 복사 대상이나 부모의 symlink를 거부하며 검사 전 준비 실패를 실제 실행과 구분합니다.
- `ha estimate`가 시작 전 필요한 최소 검증 횟수를 보여 줍니다. `ha budget`은 현재 창의 총횟수 상한만 바꾸고 기존 사용량과 시간 상한을 유지합니다.
- `ha capabilities --format json`으로 실제 사용할 Core의 지원을 확인합니다. 새 Seal은 지원하지 않는 Core로 기록을 시작하지 않으며, Spec은 Core 없이 새 `nested/1` 목표 문서를 작성할 수 있습니다.

기존 `/1`·`/2` 목표는 저장된 규칙을 유지합니다. 목표·과거 기록을 자동 이전하거나 시간 상한을 변경하지 않습니다. 기존 `v0.1.2` 태그와 파일은 보존하며, 그 버전의 Core·플러그인 조합을 새 조합과 혼용하지 마세요.

[설치·업데이트 안내](https://github.com/jgoneit/jaekit/blob/v0.1.3/guides/INSTALL.md)에 따라 Core와 플러그인을 함께 갱신합니다. Codex marketplace는 `jgoneit/jaekit@v0.1.3`, Claude Code marketplace는 `jgoneit/jaekit#v0.1.3`에 고정합니다. 현재 PATH의 실제 실행 파일과 새 호스트 세션의 Skill 출처를 확인하세요.

첨부한 `ha_0.1.3_<os>_<arch>.tar.gz` 네 파일은 `checksums.txt`로 검증할 수 있습니다. 각 아카이브에는 실행 파일·라이선스·공개 문서와 함께 `tools/check-result-reference.py`, `examples/check-result/`가 들어 있습니다. Homebrew 설치에서는 같은 지원 파일을 `$(brew --prefix jaekit)/share/jaekit`에서 찾습니다. [참조 검사 예시](https://github.com/jgoneit/jaekit/blob/v0.1.3/examples/check-result/README.md)의 파일을 자신의 프로젝트에 복사하면 개발 checkout 없이 사용할 수 있습니다.

참조 생산자는 Python 3 표준 라이브러리를 사용하는 선택적 예시입니다. Python과 특정 테스트 러너가 Core·Spec·Seal 전체의 필수 조건이 되는 것은 아닙니다. pytest·Vitest·Playwright 어댑터가 내장되거나 모든 스크립트가 자동으로 `/3` 근거를 제공하는 것은 아닙니다.

배포 검증은 네 플랫폼의 빌드·실행 파일 형식·아카이브 내용·체크섬을 확인하고, Linux amd64에서 압축한 Core의 버전·지원 조회와 포함된 참조 생산자의 실제 위반→통과를 실행합니다. 다른 플랫폼의 빌드 성공을 그 플랫폼에서 실행한 결과로 대신하지 않습니다. 이 검사는 Codex·Claude의 실제 모델 수행이나 모든 환경의 동작을 보증하지 않습니다.
