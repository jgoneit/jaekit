Jaekit v0.1.5는 Core `ha 0.1.5`, Spec `0.1.12`, Seal `0.1.16` 조합입니다. macOS·Linux의 arm64·amd64를 지원합니다. 이번 릴리스에도 Windows 파일은 없습니다.

이번 변경:

- Seal 0.1.16은 새 목표를 `run-rules/4`로 시작합니다. 시작 요청을 시험 변경 권한으로 읽었으면 그 해석을 남기고, 조건과 확인 방법을 밝힌 시험 변경(`test-change`)만 면제합니다. 사용자 답을 기다린 시간은 `wait`·`resume`으로 신고해 경과 시간 예산에서 빼고, 사용자가 미리 승인한 횟수 상한 안에서는 이유만으로 상한을 올리며, 오류 한도를 넘은 조건은 바뀐 실행 조건을 밝힌 `recover`로 다시 시도합니다. PLAN의 `## 시간 제한`은 명령별 시간 제한을 정하고, `ha check`는 실행 전에 이전 실행의 제한 사용을 안내합니다. 실행자의 근거·신고·회복 사유는 주장이며 Core는 기록과 연결만 확인합니다.
- Core의 기본 규칙은 `/3` 그대로입니다. `/4`는 `ha start --rules run-rules/4`로만 고르며, 기존 `/1`·`/2`·`/3` 목표는 저장된 규칙·사용량·시간 한도를 유지합니다. Seal 0.1.16은 새 시작에서 실제 Core의 `run-rules/4`와 다섯 기능(`test-authority/v1`, `reported-wait/v1`, `preapproved-runs/v1`, `error-recovery/v1`, `command-time-limits/v1`)을 확인하고, 하나라도 없으면 기록 전에 멈춥니다.
- `ha history`는 실행 기록과 분리된 판단 이력(관측·원인·결정·조치·검증·막힘·재개)을 등록·정정·조회합니다. 이력은 완료 판정·예산·검사 결과를 바꾸지 않습니다.
- `check`·`baseline` 기록이 실행 시간, 적용한 시간 제한과 제한 구간, CPU 시간을 남기고, `ha timing`이 읽기 전용 시간 보기를 제공합니다. 측정값은 판정과 예산에 쓰이지 않습니다.
- `ha status`는 남은 일을 먼저 보여 주고, 실패한 대상마다 볼 로그(`ha log <goal> <seq>`)를 알려 줍니다.
- Seal 0.1.14는 검사가 무엇을 읽는지에 대한 작성 안내를, Seal 0.1.15는 공식 근거를 최종 후보에서 한 번 기록하는 안내를 더했습니다.
- 아카이브의 공개 자료에 WSL2 Ubuntu 24.04 안내와 환경 확인 도구(`tools/wsl/check-environment.sh`)가 들어 있습니다. 실제 WSL 환경에서의 확인은 아직 남아 있습니다.

판단 이력·시간 보기·`/4`는 실제 Core의 지원 정보(`ha capabilities --format json`)를 확인한 뒤 사용합니다. 이전 `v0.1.4`에는 이 셋이 없습니다.

[설치·업데이트 안내](https://github.com/jgoneit/jaekit/blob/v0.1.5/guides/INSTALL.md)에 따라 Core와 플러그인을 함께 갱신합니다. Codex marketplace는 `jgoneit/jaekit@v0.1.5`, Claude Code marketplace는 `jgoneit/jaekit#v0.1.5`에 고정합니다. 현재 PATH의 실제 실행 파일과 새 호스트 세션의 Skill 출처를 확인하세요. Core만 갱신하고 Seal을 이전 버전으로 두면 새 목표는 계속 `/3`으로 시작하고, Seal만 0.1.16으로 올리고 Core를 이전 버전으로 두면 새 시작이 기록 전에 멈춥니다.

첨부한 `ha_0.1.5_<os>_<arch>.tar.gz` 네 파일과 `checksums.txt`를 함께 사용합니다. 아카이브에는 실행 파일·라이선스·공개 문서·참조 검사 예시가 포함됩니다. Homebrew 설치의 지원 파일은 `$(brew --prefix jaekit)/share/jaekit`에 있습니다. 참조 검사는 Python 3 표준 라이브러리를 사용하는 선택 사항이며, Python이나 특정 시험 러너가 Core·Spec·Seal 전체의 필수 조건은 아닙니다.

배포 검증은 네 플랫폼 빌드, 실행 파일 형식, 아카이브 내용과 체크섬을 확인하고 Linux amd64에서 압축한 Core와 참조 검사를 실행합니다. 다른 플랫폼의 빌드 성공을 해당 플랫폼의 실제 실행 결과로 대신하지 않으며, Codex·Claude의 실제 모델 수행을 보증하지 않습니다. Windows CI의 결과는 현재 소스의 로컬 후보에 대한 것이며 이번 릴리스의 Windows 지원을 뜻하지 않습니다.
