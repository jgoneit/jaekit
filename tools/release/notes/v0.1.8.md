Jaekit v0.1.8은 Core `ha 0.1.8`, 검토 실행기 `spar 0.1.8`, Spec `0.1.13`, Seal `0.1.23`, Spar `0.1.4` 조합입니다. macOS·Linux의 arm64·amd64를 지원합니다. 이번 릴리스에는 Windows 파일이 없습니다.

이번 변경:

- Core에 `ha cost`를 더했습니다. 목표 하나가 검증과 검토에 들인 비용(검사 실행의 수와 시간, 다시 기록한 실행, 예산 창, 신고한 대기와 질문, 검토 라운드와 리뷰어 시간)을 그 목표의 기록과 `--series`로 가리킨 Spar series 폴더에서 모아 숫자로 보입니다. 기록을 읽기만 하고 아무것도 쓰지 않으며, 현재 시각을 읽지 않고 모델을 부르지 않습니다. [사용 안내](https://github.com/jgoneit/jaekit/blob/v0.1.8/guides/USAGE.md)를 보세요.
- Seal 0.1.23은 목표 문서·계획·프로젝트 지침·코드에서 미리 알 수 있는, 사용자의 말이 필요한 결정을 첫 baseline 전에 한 메시지로 묻습니다. 계획이 더하는 시험·검사 파일은 처음부터 계획의 변경 범위에 넣습니다. Seal의 `ha` 설치 경로와 릴리스 링크는 이 릴리스를 가리킵니다.
- Spar 0.1.4의 리뷰어는 지적마다 가장 작은 수정 방향을 함께 낼 수 있고, 라운드 기록(`findings.json`, `summary.md`)이 그 방향을 담습니다. 빈 값일 수 있습니다.
- README에 사용 흐름 그림과 짧아진 데모를 넣었습니다.
- 업데이트 확인이 `ha`와 함께 `spar`의 버전과 PATH가 고르는 위치를 봅니다(README와 설치 안내가 같은 명령).
- 직접 설치 명령은 압축을 푼 파일에 `spar`가 없으면 어느 실행 파일도 바꾸지 않고 메시지와 함께 멈춥니다.

Core의 기본 규칙은 계속 `/3`이고, Seal은 새 목표를 `run-rules/5`로 시작합니다. 기존 목표는 저장된 규칙·완료 기록·사용량·시간 한도를 유지합니다. Spec은 Core 없이 목표 문서를 씁니다.

[설치·업데이트 안내](https://github.com/jgoneit/jaekit/blob/v0.1.8/guides/INSTALL.md)에 따라 Core와 세 플러그인을 함께 갱신합니다. Codex marketplace는 `jgoneit/jaekit@v0.1.8`, Claude Code marketplace는 `jgoneit/jaekit#v0.1.8`에 고정합니다. 현재 PATH에서 실제로 실행되는 `ha`·`spar`와 새 호스트 세션의 Skill 출처를 확인하세요.

첨부한 `ha_0.1.8_<os>_<arch>.tar.gz` 네 파일과 `checksums.txt`를 함께 사용합니다. 각 아카이브에는 `ha`·`spar`·라이선스·공개 문서·참조 검사 예시가 들어 있습니다. Homebrew 설치의 지원 파일은 `$(brew --prefix jaekit)/share/jaekit`에 있습니다. 참조 검사는 Python 3 표준 라이브러리를 사용하는 선택 사항이며, Python이나 특정 시험 러너가 Core·Spec·Seal 전체의 필수 조건은 아닙니다.

확인한 범위:

- 릴리스 워크플로는 네 플랫폼 빌드, 실행 파일 형식, 아카이브 내용(`ha`·`spar`)과 체크섬을 확인하고, Linux amd64에서 압축한 `ha`·`spar`와 참조 검사를 실행합니다.
- 태그를 만들기 전에 이 커밋에서 CI가 만든 후보 파일과 이 커밋의 세 플러그인으로, macOS arm64의 Claude Code에서 새 합성 프로젝트의 `standard` 목표 하나를 Spec 작성부터 Spar 검토 gate와 `ha done`까지 돌립니다. Seal이 첫 baseline 전에 미리 알 수 있는 결정을 한 메시지로 묻는 것, 라운드 기록의 수정 방향 칸, gate를 기록하기 전의 `ha done`이 완료를 기록하지 않는 것을 확인합니다. 이 확인이 끝나지 않으면 태그를 만들지 않습니다.

확인하지 않은 범위:

- 공개 경로의 설치. Homebrew와 직접 설치의 v0.1.7 업그레이드, Claude Code·Codex의 marketplace 갱신과 Skill 로딩, 기존 목표의 상태 유지는 이 본문을 게시한 뒤 macOS arm64에서 공개 파일로 확인합니다. 이 본문은 그 결과를 담지 않습니다.
- Windows 네이티브와 WSL2의 실제 설치·실행. Windows CI의 결과는 현재 소스의 로컬 후보에 대한 것이며 이번 릴리스의 Windows 지원을 뜻하지 않습니다.
- Linux arm64와 macOS amd64에서의 실제 실행. 빌드 성공을 해당 플랫폼의 실행 결과로 대신하지 않습니다.
- Codex에서 목표를 끝까지 돌리는 흐름(Codex는 게시 뒤 설치와 Skill 로딩만 확인합니다), Codex·Claude의 실제 모델 수행 품질.

남은 이슈 중 [다른 base에서 시작한 gate의 수용](https://github.com/jgoneit/jaekit/issues/148), [`run-rules/5`의 완료 판정 사례](https://github.com/jgoneit/jaekit/issues/150), [판정하지 않은 뒤 `done` 줄](https://github.com/jgoneit/jaekit/issues/151), [Spar 첫 라운드의 설정 안내](https://github.com/jgoneit/jaekit/issues/166), [WSL2 실제 환경 확인](https://github.com/jgoneit/jaekit/issues/92)은 후속 대상입니다. 현재 배포 입력과 실행 경로에서는 출시 차단 조건을 확인하지 못했습니다.
