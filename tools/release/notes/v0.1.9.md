Jaekit v0.1.9는 Core `ha 0.1.9`, 검토 실행기 `spar 0.1.9`, Spec `0.1.16`, Seal `0.1.36`, Spar `0.1.9` 조합입니다. 직전 릴리스 v0.1.8은 `ha`·`spar` `0.1.8`, Spec `0.1.13`, Seal `0.1.23`, Spar `0.1.4` 조합이었습니다. macOS·Linux의 arm64·amd64를 지원합니다. 이번 릴리스에는 Windows 파일이 없습니다.

이번 변경:

- Seal 0.1.36은 새 목표를 `run-rules/8`로 시작합니다(Seal 0.1.23은 `/5`). `/5`와 달리 마지막 candidate 라운드의 base가 목표의 시작 커밋이 아니면 완료하지 않고(`review_base_mismatch`), 판정하지 않은 `done` 줄은 상태 계산에서 빠지며, 완료 뒤의 시간은 경과 시간에서 빠져 따로 보입니다. PLAN 조건표의 `baseline` 열에 `요구`로 표시한 change 조건만 baseline이 필요하고, 표시한 조건들의 검사 경로를 함께 겹쳐 기록하므로 조건끼리 helper를 나눠 쓸 수 있습니다. 경과 시간은 정보로만 보여 한도를 넘어도 `budget_exceeded`가 되지 않고, `ha budget --preapprove`는 거부합니다. Core는 `run-rules/6`·`/7`도 지원합니다.
- Seal은 두 경우에만 change 조건에 baseline `요구`를 표시합니다. base 커밋에 이미 있는 결함과 "X가 일어나지 않는다" 같은 금지입니다. 나머지는 표시하지 않고 통과하는 현재 검사로 충족하며, baseline은 마지막 검토 라운드 뒤 완료 기록 바로 전에 기록합니다.
- `run-rules/8`의 PLAN 조건에 `review` 종류를 더했습니다. 제품 동작이 읽지 않는 문서 내용이 결과인 기준에 쓰며, `standard`·`strict` 목표의 검토 gate로 충족하므로 문서 문장을 고정하는 시험이 필요 없습니다. `light` 목표나 `Assurance:` 줄이 없는 목표에서는 `review_tier_missing`(사용자)이 되어 `ha done`이 완료를 기록하지 않습니다. `ha estimate`는 이 줄에 실행 0회를 세고, `ha check`는 이 줄을 거부하며, `ha report`는 검토 gate로 충족한 조건을 보입니다.
- 완료한 목표의 `PROGRESS.md`에 `## 검수 요약`을 씁니다. 여는 줄(완료 기록, 등급, 충족한 조건 수, 검토 gate)과 `### 바뀐 것`·`### 근거`·`### 직접 볼 것`·`### 보지 않은 것` 네 제목으로, 무엇이 바뀌었고 무엇을 근거로 했으며 사람이 무엇을 직접 봐야 하는지 한곳에 모읍니다. reopen 뒤에는 다음 완료 기록에 맞춰 다시 쓰고, 완료한 목표의 PR 설명은 이 요약에서 만듭니다.
- Seal은 `REVIEW.md`의 `## 중요한 미결정`을 `### 사용자의 답`과 `### 실행자 가정`으로 나눠 적고, 사용자가 정한 결정을 검토 라운드마다 Spar에 넘겨 리뷰어가 이미 정한 전제를 다시 지적하지 않게 합니다. Seal skill은 지금 시작하는 목표의 규칙만 적고, 이전 규칙은 계약 문서로 링크합니다. Spec 0.1.16은 새 결정 앞에 출처 표시 `[사용자]`·`[제안]`·`[기존]`을 붙입니다.
- Spar 0.1.9의 새 라운드는 `plan`과 `candidate`로만 시작하고, 기본 code 라운드 상한은 3에서 2로 내려갑니다. 이전 code 라운드가 있는 candidate 라운드(누적 라운드 포함)는 그 라운드들의 지적과 마지막 처리를 받고, 리뷰어에게 기록된 처리가 답하지 않는 실패 시나리오가 있을 때만 같은 지적을 다시 내라고 요청합니다. 이미 기록된 series는 전처럼 읽습니다.
- `spar run`에 옵션을 더했습니다. `--decision`·`--decision-quote`(사용자의 결정과 그 말), `--boundary FILE`(검사 경계 문서), `--text-check GLOB`(고정 문구만 읽는 검사), `--standpoint NAME=TEXT`(리뷰어마다 먼저 공격할 관점), 사용자 설정이 비워 둔 리뷰어에만 쓰는 `--model NAME=MODEL`·`--effort NAME=EFFORT`(`allowed_models`·`allowed_efforts`로 제한)입니다. 관점을 받은 리뷰어는 `standpoint_report`를 내야 하고, gate는 재실행까지 보고도 완료한 리뷰어가 없는 관점을 `uncovered_standpoints`로 적습니다. waive된 리뷰어의 관점도 여기에 남습니다.
- `spar cap-report SERIES`는 code 상한을 다 쓴 까닭을 기록과 Git 이력만 읽어 네 신호로 보이고(검사 비대는 이전 릴리스가 기록한 fixes 라운드에서만 재므로, 새 series에서는 재지 않았다고 표시합니다), `spar extend --stage code`는 `--cause`(`churn`·`recurring`·`unrelated`·`hardening`·`other`)를 요구합니다. 리뷰어마다 패킷 크기 한도 `max_packet_bytes`가 있어 넘는 패킷은 리뷰어를 시작하기 전에 거부합니다. agy는 읽기 전용 명령을 `|`·`&&`·`||`·`;`로 이을 수 있고, `spar record`는 아무것도 쓰기 전에 라운드의 지적과 ledger를 확인합니다.
- `spar gate`는 사람이 미룬 지적(`deferred_findings`)과 처리 없는 지적(`unhandled_findings`)을 적고, `ha note review --gate`가 이를 남기며, `ha report`의 `직접 볼 것` 줄이 보입니다. 판정은 이 목록을 읽지 않습니다. `ha cost`는 상한 연장마다 원인과 이유, 완료 뒤 시간을 보이고, `ha --help`가 `ha cost`를 적습니다.
- 저장소에서 만드는 [문서 사이트](https://jgoneit.github.io/jaekit/)를 열었고, 처음 읽는 사람을 위한 [Jaekit 이해하기](https://github.com/jgoneit/jaekit/blob/v0.1.9/guides/OVERVIEW.md)와 개발 안내를 더했습니다. 안내(`guides/`)는 한국어와 영어 두 판(`X.md`, `X.en.md`)이고, 계약(`contracts/`)은 문서마다 영어 파일 하나입니다. README는 첫 `standard` 목표 전에 `docs/reviews/`를 `.gitignore`에 넣어 커밋하고 가진 리뷰어 CLI만 `~/.config/jaekit/spar.toml`에 적으라고 안내하며, `ha`에 필요한 Git 2.36 이상을 적습니다.
- 줄인 것: `ha history`와 판단 기록 형식(`decision-history/v1` 등)을 없앴습니다. 이전 릴리스가 공통 Git 폴더의 `ha/history/`에 남긴 기록은 지우지 않으며, 읽으려면 v0.1.8을 씁니다. `spar run --stage plan-delta`·`fixes`는 사용 오류(64)로 끝나고, `[caps] plan_delta` 설정은 읽고 기록하지만 새 라운드에 쓰지 않습니다. 세 skill 본문은 드문 경우의 규칙을 참조 문서로 옮겨 짧아졌습니다.

Core의 기본 규칙은 계속 `/3`이고, Seal은 새 목표를 `run-rules/8`로 시작합니다. Seal 0.1.36은 `run-rules/8`을 지원하는 Core가 필요해 `ha 0.1.8`에서는 기록 없이 멈춥니다. 기존 목표는 저장된 규칙·완료 기록·사용량·시간 한도를 유지합니다. Spec은 Core 없이 목표 문서를 씁니다.

[설치·업데이트 안내](https://github.com/jgoneit/jaekit/blob/v0.1.9/guides/INSTALL.md)에 따라 Core와 세 플러그인을 함께 갱신합니다. Codex marketplace는 `jgoneit/jaekit@v0.1.9`, Claude Code marketplace는 `jgoneit/jaekit#v0.1.9`에 고정합니다. 현재 PATH에서 실제로 실행되는 `ha`·`spar`와 새 호스트 세션의 Skill 출처를 확인하세요.

첨부한 `ha_0.1.9_<os>_<arch>.tar.gz` 네 파일과 `checksums.txt`를 함께 사용합니다. 각 아카이브에는 `ha`·`spar`·라이선스·공개 문서·참조 검사 예시가 들어 있습니다. Homebrew 설치의 지원 파일은 `$(brew --prefix jaekit)/share/jaekit`에 있습니다. 참조 검사는 Python 3 표준 라이브러리를 사용하는 선택 사항이며, Python이나 특정 시험 러너가 Core·Spec·Seal 전체의 필수 조건은 아닙니다.

확인한 범위:

- 릴리스 워크플로는 릴리스 커밋에서 후보 아카이브를 빌드하고, `check_archives.py --require-spar`로 네 플랫폼의 실행 파일 형식, 아카이브 내용(`ha`·`spar`)과 체크섬을 확인하며, Linux amd64에서 압축한 `ha`·`spar`와 참조 검사를 실행합니다.
- 태그를 만들기 전에 이 커밋에서 CI가 만든 후보 `ha`·`spar`와 이 커밋의 세 플러그인으로, macOS arm64의 Claude Code에서 새 합성 프로젝트의 `standard` 목표 하나를 Spec 작성부터 Spar 검토 gate와 `ha done`까지 돌립니다. Seal이 목표를 `run-rules/8`로 시작하는 것, 라운드 기록에 리뷰어마다 모델과 그 출처가 남는 것, gate를 기록하기 전의 `ha done`은 완료를 기록하지 않고 기록한 뒤에는 기록하는 것, 완료 뒤 `PROGRESS.md`의 `## 현재` 바로 다음에 `## 검수 요약`이 있고 `## 완료 보고`가 `ha report` 출력을 그대로 담는 것, `ha report`와 `ha cost`가 그 목표를 보이는 것을 확인합니다. 이 확인이 끝나지 않으면 태그를 만들지 않습니다.

확인하지 않은 범위:

- 공개 경로의 설치. Homebrew와 직접 설치의 v0.1.8 업그레이드, Claude Code·Codex의 marketplace 고정과 플러그인 설치, 새 호스트 세션의 Skill 로딩, v0.1.8로 시작한 기존 목표의 상태 유지와 새 `spar gate`·`ha cost`가 `spar 0.1.8`의 series를 같게 읽는지는 태그를 만들고 이 본문을 게시한 뒤 macOS arm64 한 대에서 공개 파일로 확인합니다. 이 본문은 그 결과를 담지 않습니다.
- Windows 네이티브와 WSL2 실제 환경의 설치·실행. 이번 릴리스에는 Windows 파일이 없고, Windows CI의 결과는 현재 소스의 로컬 후보에 대한 것이며 이번 릴리스의 Windows 지원을 뜻하지 않습니다.
- CI 밖의 Linux 호스트(Linux arm64 포함)와 macOS amd64에서의 실제 실행. 빌드 성공을 해당 플랫폼의 실행 결과로 대신하지 않습니다.
- Codex에서 목표를 끝까지 돌리는 흐름(Codex는 게시 뒤 플러그인 설치와 Skill 로딩만 확인합니다), Codex·Claude의 실제 모델 수행 품질.

남은 이슈 중 [plan 라운드 뒤 목표 문서를 바꾼 `strict` 목표의 plan 상한 연장](https://github.com/jgoneit/jaekit/issues/293), [필수 조건이 풀려 무효가 된 완료의 이유 표시](https://github.com/jgoneit/jaekit/issues/315), [필수 `review` 조건이 있는 `light` 목표에서 미리 묻기](https://github.com/jgoneit/jaekit/issues/316), [`run-rules/8`의 경과 시간 표시와 진단](https://github.com/jgoneit/jaekit/issues/307), [WSL2 실제 환경 확인](https://github.com/jgoneit/jaekit/issues/92)은 후속 대상입니다. 현재 배포 입력과 실행 경로에서는 출시 차단 조건을 확인하지 못했습니다.
