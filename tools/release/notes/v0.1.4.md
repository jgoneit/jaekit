Jaekit v0.1.4는 Core `ha 0.1.4`, Spec `0.1.12`, Seal `0.1.12` 조합입니다. macOS·Linux의 arm64·amd64를 지원합니다.

이번 변경:

- 완료 뒤 발견한 문제를 기존 완료 기록과 함께 보존합니다. `ha finding`은 대상 버전·조건·재현 범위·해결 연결을 기록하고, 같은 입력의 재시도는 기록을 중복 추가하지 않습니다. 발견을 남기는 것만으로 목표를 재개하거나 예산을 바꾸지 않습니다.
- Spec은 원하는 결과와 결정 경계를 더 명확히 구분합니다. Seal의 검토·완료 보고는 검증의 근거, 실제 관측 범위, 대체 환경과 남은 한계를 연결하고 목표·프로젝트가 정한 보증 정책을 반영합니다. 기존 목표나 완료 보고를 소급해서 다시 쓰지 않습니다.
- 공통 Go 검증에서 시험을 줄이는 환경 필터를 검사 프로세스에 한해 해제하고 알립니다. 회귀 보호 대상은 지원하는 정적 판독 범위에서 실제 Go 선언·빌드 선택과 Python discovery·선택 패턴을 기준으로 확인합니다.
- 릴리스 검사에서 아카이브 읽기 한도, 설치 경로와 실제 실행 파일의 연결, 검사 생산자의 import 경로와 실패 귀속을 보강했습니다. 부모 symlink를 포함한 설치 경로도 실제 경로와 연결해 확인합니다.

기본 규칙은 `/3`이며 기존 `/1`·`/2`·`/3` 목표는 저장된 규칙·사용량·시간 한도를 유지합니다. 완료 뒤 발견은 실제 Core의 `run-finding/v1`·`post-completion-findings/v1` 지원을 확인한 뒤 사용합니다. 이전 `v0.1.3`에는 이 확장이 없습니다.

[설치·업데이트 안내](https://github.com/jgoneit/jaekit/blob/v0.1.4/guides/INSTALL.md)에 따라 Core와 플러그인을 함께 갱신합니다. Codex marketplace는 `jgoneit/jaekit@v0.1.4`, Claude Code marketplace는 `jgoneit/jaekit#v0.1.4`에 고정합니다. 현재 PATH의 실제 실행 파일과 새 호스트 세션의 Skill 출처를 확인하세요.

첨부한 `ha_0.1.4_<os>_<arch>.tar.gz` 네 파일과 `checksums.txt`를 함께 사용합니다. 아카이브에는 실행 파일·라이선스·공개 문서·참조 검사 예시가 포함됩니다. Homebrew 설치의 지원 파일은 `$(brew --prefix jaekit)/share/jaekit`에 있습니다. 참조 검사는 Python 3 표준 라이브러리를 사용하는 선택 사항이며, Python이나 특정 시험 러너가 Core·Spec·Seal 전체의 필수 조건은 아닙니다.

배포 검증은 네 플랫폼 빌드, 실행 파일 형식, 아카이브 내용과 체크섬을 확인하고 Linux amd64에서 압축한 Core와 참조 검사를 실행합니다. 다른 플랫폼의 빌드 성공을 해당 플랫폼의 실제 실행 결과로 대신하지 않으며, Codex·Claude의 실제 모델 수행을 보증하지 않습니다.

남은 이슈 중 [비정상 아카이브의 보조 한도](https://github.com/jgoneit/jaekit/issues/49)와 [정적 선택 분석](https://github.com/jgoneit/jaekit/issues/58), [추가 관측기의 기대 실패 분류](https://github.com/jgoneit/jaekit/issues/59), [하위 검사 입력 선언](https://github.com/jgoneit/jaekit/issues/60)은 후속 보강 대상입니다. 현재 배포 입력과 실행 경로에서는 출시 차단 조건을 확인하지 못했습니다. 과거 v0.1.3 전용 관측기의 결과를 이번 릴리스 증거로 재사용하지 않습니다.
