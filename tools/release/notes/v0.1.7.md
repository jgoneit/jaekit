Jaekit v0.1.7은 Core `ha 0.1.7`, 검토 실행기 `spar 0.1.7`, Spec `0.1.13`, Seal `0.1.22`, Spar `0.1.3` 조합입니다. macOS·Linux의 arm64·amd64를 지원합니다. 이번 릴리스에는 Windows 파일이 없습니다.

이번 변경:

- Spar를 처음 배포합니다. `spar`는 계획이나 변경 하나를 설정한 여러 리뷰어 CLI(기본 claude·codex·agy)에 같은 패킷으로 보내 독립 검토 라운드를 돌리고, 지적을 정해진 규칙으로 분류하고 처리를 기록하며, 검토 gate 파일(`review-gate/v1`)을 씁니다. 각 아카이브와 Homebrew formula는 `ha`와 같은 버전의 `spar`를 함께 설치합니다. Spar 플러그인은 Claude Code에서 `/spar:spar`, Codex에서 `$spar:spar`로 부릅니다. [Spar 안내](https://github.com/jgoneit/jaekit/blob/v0.1.7/guides/SPAR.md)를 보세요.
- Seal은 새 목표를 `run-rules/5`로 시작합니다. `/5`는 `/4`의 자율 처리를 그대로 두고, SPEC의 등급(`Assurance:` 줄)이 `standard`·`strict`인 목표는 기록된 Spar gate가 HEAD와 목표 문서를 덮어야 `ha done`이 완료를 기록합니다. `light` 목표, `Assurance:` 줄이 없는 목표, `run-rules/4` 이하로 시작한 목표에는 Spar가 필요 없습니다.
- Core에 `ha report`(사람용 요약·도장·조건별 근거·완료 범위), `ha doctor`(PLAN `## 실행 환경`의 도구 점검), `검증 실행: 자동`(시작 때 횟수 상한 산정과 사용자의 사전 승인 상한), skill의 Core 요구 선언과 `ha start --check-skill`을 더했습니다. Seal은 이 선언으로 필요한 지원을 확인하고, 지원이 없는 `ha`에서는 기록 없이 멈춥니다.
- 러너 어댑터: change 조건이 전용 생산자 없이 `go test -json` 출력이나 JUnit XML로 기존 시험에 대상을 연결할 수 있습니다(`check-adapter/v1`).
- Seal skill을 줄이고 세부 규칙을 참조 문서로 옮겼습니다. Seal의 `ha` 설치 경로는 `--check-skill`을 지원하는 이 릴리스의 안내를 가리킵니다.
- Spec은 사용자뿐 아니라 호스트 에이전트도 부를 수 있습니다. `Ready`와 구현 시작은 사용자의 말로만 정해지며, 남은 결정이 없으면 지금 구현할지 묻습니다. 목표 문서에 검토 등급(`Assurance:`)과 수정 문서를 더했습니다.
- README와 설치 안내의 Claude Code·Codex 설치·업데이트 명령이 `spec`·`seal`·`spar` 세 플러그인을 설치합니다. 아카이브의 루트 문서는 `README.md`(영어)와 `README.ko.md`(한국어)이고, 직접 설치 명령과 Homebrew formula가 이 둘을 공개 자료로 둡니다.

Core의 기본 규칙은 계속 `/3`입니다. 기존 `/1`·`/2`·`/3`·`/4` 목표는 저장된 규칙·완료 기록·사용량·시간 한도를 유지하고 `/5`로 옮겨지지 않습니다. Spec은 Core 없이 목표 문서를 씁니다.

[설치·업데이트 안내](https://github.com/jgoneit/jaekit/blob/v0.1.7/guides/INSTALL.md)에 따라 Core와 세 플러그인을 함께 갱신합니다. Codex marketplace는 `jgoneit/jaekit@v0.1.7`, Claude Code marketplace는 `jgoneit/jaekit#v0.1.7`에 고정합니다. 현재 PATH에서 실제로 실행되는 `ha`·`spar`와 새 호스트 세션의 Skill 출처를 확인하세요.

첨부한 `ha_0.1.7_<os>_<arch>.tar.gz` 네 파일과 `checksums.txt`를 함께 사용합니다. 각 아카이브에는 `ha`·`spar`·라이선스·공개 문서·참조 검사 예시가 들어 있습니다. Homebrew 설치의 지원 파일은 `$(brew --prefix jaekit)/share/jaekit`에 있습니다. 참조 검사는 Python 3 표준 라이브러리를 사용하는 선택 사항이며, Python이나 특정 시험 러너가 Core·Spec·Seal 전체의 필수 조건은 아닙니다.

확인한 범위:

- 릴리스 워크플로는 네 플랫폼 빌드, 실행 파일 형식, 아카이브 내용(`ha`·`spar`)과 체크섬을 확인하고, Linux amd64에서 압축한 `ha`·`spar`와 참조 검사를 실행합니다.
- 태그를 만들기 전에 이 커밋에서 CI가 만든 후보 파일과 이 커밋의 세 플러그인으로, macOS arm64의 Claude Code에서 새 합성 프로젝트의 `standard` 목표 하나를 Spec 작성부터 Spar 검토 gate와 `ha done`까지 돌리고, gate를 기록하기 전의 `ha done`이 완료를 기록하지 않는 것을 확인합니다. 이 확인이 끝나지 않으면 태그를 만들지 않습니다.

확인하지 않은 범위:

- 공개 경로의 설치. Homebrew와 직접 설치의 v0.1.6 업그레이드, Claude Code·Codex의 marketplace 갱신과 Skill 로딩, 기존 목표의 상태 유지는 이 본문을 게시한 뒤 macOS arm64에서 공개 파일로 확인합니다. 이 본문은 그 결과를 담지 않습니다.
- Windows 네이티브와 WSL2의 실제 설치·실행. Windows CI의 결과는 현재 소스의 로컬 후보에 대한 것이며 이번 릴리스의 Windows 지원을 뜻하지 않습니다.
- Linux arm64와 macOS amd64에서의 실제 실행. 빌드 성공을 해당 플랫폼의 실행 결과로 대신하지 않습니다.
- Codex에서 목표를 끝까지 돌리는 흐름(Codex는 게시 뒤 설치와 Skill 로딩만 확인합니다), Codex·Claude의 실제 모델 수행 품질.

남은 이슈 중 [다른 base에서 시작한 gate의 수용](https://github.com/jgoneit/jaekit/issues/148), [`run-rules/5`의 완료 판정 사례](https://github.com/jgoneit/jaekit/issues/150), [판정하지 않은 뒤 `done` 줄](https://github.com/jgoneit/jaekit/issues/151), [Spar의 후속 보강](https://github.com/jgoneit/jaekit/issues/152), [WSL2 실제 환경 확인](https://github.com/jgoneit/jaekit/issues/92)은 후속 대상입니다. 현재 배포 입력과 실행 경로에서는 출시 차단 조건을 확인하지 못했습니다.
