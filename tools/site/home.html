Check the record.

Jaekit은 Claude Code·Codex에 더해 쓰는 플러그인과 터미널 프로그램입니다. 일을 맡기기 전에 무엇을 하면 끝인지 문서로 정해 두고, 끝났는지는 에이전트의 말이 아니라 검사를 실제로 돌린 기록으로 판단합니다.

Jaekit is a set of plugins for Claude Code and Codex, plus two small terminal programs. Before the work starts, it writes down what finished means; at the end, it judges completion from records of checks that actually ran, not from the agent's word.

What “done” doesn't tell you

AI 코딩 에이전트에 일을 맡기면 이런 일이 생기곤 합니다.

Hand work to an AI coding agent and these can happen.

조건 일부가 빠져 있습니다Some conditions are missing

열 가지를 부탁했는데 일곱 가지만 하고 끝냅니다. 어려운 조건을 쉬운 조건으로 바꿔 읽기도 합니다.

You asked for ten things and got seven. A hard condition gets read as an easier one.

무엇을 검사했는지 모릅니다You can't see what was checked

“테스트를 통과했습니다”라고 하지만, 어느 코드에서 무엇을 돌렸는지는 바뀐 코드를 처음부터 읽어야 압니다.

It says “the tests pass”, but to learn what ran against which code you read the whole change yourself.

대화가 끊기면 처음부터입니다A new conversation starts from zero

새 대화에서는 무엇을 약속했고 어디까지 했는지 다시 설명해야 합니다.

In a new conversation you explain again what was promised and how far it got.

무엇이 달라지나What changes

Jaekit이 있으면 기록이 남고, 없으면 말만 남습니다.

With Jaekit you get a record. Without it, just words.

같은 일을 대화로만 맡길 때와 Jaekit으로 맡길 때를 나란히 놓았습니다. 어느 쪽이든 일은 같은 에이전트가 합니다.

The same work, handed over in a plain conversation and through Jaekit. Either way, the same agent does the work.

작동 방식How it works

내가 하는 일은 세 가지입니다.

You do three things.

말하고, 확인하고, 읽습니다. 그 사이의 계획·구현·검사는 쓰던 에이전트가 합니다. 일은 에이전트 대화로 맡기고, 터미널은 주로 설치와 업데이트에 씁니다.

Ask, confirm, read. Your agent plans, builds and checks in between. You hand over work in the agent conversation; the terminal is mostly for installing and updating.

01Spec

원하는 일을 말합니다Describe the work

에이전트 대화에 요청을 보내면 Spec이 목표와 완료 조건을 SPEC.md에 정리하고 멈춥니다. 아직 코드는 고치지 않습니다.

Send your request in the agent conversation. Spec writes the goal and its completion conditions to SPEC.md and stops; no code changes yet.

02Seal

읽어 보고 “응”이라고 답합니다Read it and answer yes

빠진 조건이 있으면 고쳐 달라고 합니다. 맞으면, Spec이 지금 구현할지 물을 때 “응”이라고 답합니다. 그때부터 에이전트가 Seal을 따라 계획·구현·검사를 끝까지 하고, 내가 정하거나 직접 확인할 것이 있을 때만 묻습니다.

Ask for changes if a condition is missing. If it is right, reply yes when Spec asks whether to implement now. From then on your agent follows Seal to plan, build and check to the end, and asks only when something is yours to decide or to check.

에이전트가 실행 → ha check · spar · ha doneyour agent runs → ha check · spar · ha done
03ha

완료 보고를 읽습니다Read the report

필수 조건이 모두 검사 기록이나 내 확인으로 충족돼야 ha done이 완료를 남깁니다. 무엇이 바뀌었고 무엇을 확인했는지 보고가 PROGRESS.md에 붙습니다.

ha done records completion only when every required condition is met by a check record or your confirmation. A report of what changed and what was checked lands in PROGRESS.md.

네 부품 · 누가 무엇을 하나Four parts · who does what

Spec목표를 정리하는 지침Instructions for the goal

에이전트가 요청을 목표 문서로 옮길 때 따르는 지침입니다. 목표와 완료 조건, 검토 등급을 쓰고 멈춥니다.

What your agent follows to turn a request into a goal document. It writes the goal, the completion conditions and a review tier, then stops.

Seal끝까지 가게 하는 지침Instructions to finish

확인한 목표대로 에이전트가 계획·구현·검사·수정을 이어 가게 합니다. 목표 문서는 읽기만 합니다.

Keeps your agent planning, building, checking and fixing against the confirmed goal. It only reads the goal document.

ha기록하고 계산하는 프로그램The program that records

에이전트가 ha check로 돌린 검사를 모두 기록하고, 그 기록과 목표 폴더의 문서, Git으로 완료를 계산합니다. AI 모델을 부르지 않습니다.

Records every check your agent runs through ha check, and works out completion from those records, the documents in the goal folder and Git. It never calls an AI model.

Spar다른 AI에게 받는 검토Review by other AIs

작업한 에이전트의 대화 밖에 있는 리뷰어에게 같은 자료를 보내 검토를 받고, 지적과 그 처리를 기록합니다.

Sends the same material to reviewers outside the working agent's conversation, and records what they find and how each finding was handled.

알아둘 점Before you start

무엇을 보장하고, 무엇은 아닌지.

What it promises, and what it doesn't.

기록은 내 프로젝트에 남습니다Records stay in your project

목표와 계획, 진행 기록은 docs/specs/<goal>/에 파일로 남습니다. 설치·업데이트·제거가 지우지 않습니다.

Goals, plans and progress are files in docs/specs/<goal>/. Installing, updating or uninstalling never deletes them.

완료 계산에 AI를 쓰지 않습니다No AI decides completion

ha는 정해진 규칙으로만 계산하는 프로그램입니다. 기록과 목표 폴더의 문서, Git 상태가 같으면 결과도 같습니다.

ha is a program that applies fixed rules. The same record, the same documents in the goal folder and the same Git state give the same result.

완료는 “결함 없음”이 아닙니다Complete is not “bug-free”

정해 둔 조건이 기록으로 충족됐다는 뜻입니다. 검사도 에이전트가 쓰고 근거는 이 컴퓨터의 기록이라, 실제 결과는 사람이 함께 확인합니다.

It means the agreed conditions are met by the records. Your agent writes the checks and the evidence lives on this computer, so a person still looks at the actual result.

Spar 검토는 코드를 밖으로 보냅니다Spar review leaves your machine

Spar 검토를 받으면 리뷰어마다 기준·규칙 문서와 변경 내용(diff)을 자기 AI 제공자에게 보내고, 리뷰어가 읽은 프로젝트 파일도 함께 갈 수 있습니다. 밖으로 나가면 안 되는 코드라면 Spar를 돌리지 않습니다.

In a Spar review, each reviewer sends the criteria, the rules and the change (the diff) to its AI provider, and project files the reviewer reads can go too. If code must not leave your machine, don't run Spar.
