Claude Code and Codex sometimes skip a condition or stop early and still say "done". Jaekit writes down what finished means before the work starts, and judges completion from a check record for each condition.

작동 방식How it works

목표는 내가, 일은 에이전트가, 완료는 기록으로.

You set the goal. Your agent does the work. The record decides when it's done.

내가 하는 일은 셋입니다. 원하는 일을 말하고, 목표 문서를 확인해 "응"이라고 답하고, 완료 보고를 읽습니다. 그 사이의 계획·구현·검사는 쓰던 에이전트가 진행하고, 에이전트가 돌린 검사는 ha가 모두 기록합니다.

You do three things: say what you want, review the goal document and answer yes, and read the completion report. Your agent plans, builds and checks in between, and ha records every check it runs.

01Spec

원하는 일을 말합니다Describe the work

Spec이 목표, 사용 시나리오, 완료 조건과 검토 등급을 SPEC.md에 쓰고 멈춥니다.

Spec writes the goal, scenarios, completion conditions and a review tier to SPEC.md, then stops.

/$spec:spec 로그인에 "비밀번호 찾기" 추가add a "Forgot password" link
02Seal

확인하고 "응"이라고 답합니다Review it and answer yes

빠진 조건이 없으면 "응"이라고 답합니다. 그때부터 Seal이 에이전트에게 계획·구현·검사를 끝까지 맡깁니다. 새 동작의 검사는 바꾸기 전에 실패하고 바꾼 뒤에 통과해야 하며, standard·strict 목표는 Spar 독립 검토도 받습니다.

If no condition is missing, answer yes. Seal then has your agent plan, build and check to the end. A check for new behavior must fail before the change and pass after it, and standard and strict goals also get independent Spar review.

에이전트가 실행 → ha check · spar · ha doneyour agent runs → ha check · spar · ha done
03ha

완료 보고를 읽습니다Read the report

필수 조건이 모두 기록으로 충족돼야 ha done이 완료를 기록합니다. 바뀐 것, 확인한 것, 직접 볼 것, 남은 한계, 다음 행동을 담은 보고가 PROGRESS.md에 남습니다.

ha done records completion only when the records meet every required condition. The report in PROGRESS.md lists what changed, what was checked, what to review, remaining limits and the next step.

알아둘 점Before you start

무엇을 보장하고, 무엇은 아닌지.

What it promises, and what it doesn't.

기록은 프로젝트에 남습니다Records stay in your project

목표·계획·진행 기록은 docs/specs/<goal>/에 남고, 설치·업데이트·제거가 지우지 않습니다.

Goals, plans and progress live in docs/specs/<goal>/. Installing, updating or uninstalling never deletes them.

ha는 모델을 부르지 않습니다ha never calls a model

완료 판정은 기록에서만 나옵니다. 같은 기록이면 같은 판정입니다.

Completion is judged from the records alone. The same records give the same status.

완료는 제3자 검증이 아닙니다Completion is not third-party verification

자동 검사는 에이전트가 작성합니다. 보고의 남은 한계와 실제 결과를 함께 봅니다.

Your agent writes the automated checks. Read the report's remaining limits alongside the actual result.

Spar 검토는 밖으로 나갑니다Spar review leaves your machine

리뷰어마다 기준 문서와 diff가 든 패킷을 자기 제공자에게 보냅니다. 나가면 안 되는 코드라면 Spar를 돌리지 않습니다.

Each reviewer sends a packet with the criteria and the diff to its provider. If code must not leave your machine, don't run Spar.
